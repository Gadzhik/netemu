# Layer-2 (LAN) attacks and switch defences

This page is about attacks inside the local network, at the data link layer (L2) where switches work, and how switches defend against them. The attacker needs no software vulnerabilities here: they abuse the very design of ARP, DHCP and STP, which by default trust anyone on the network. NetEmu shows this: the "LAN attacker" device runs attacks with real frames, and the defences are configured on the switch exactly as on real Cisco equipment.

> The attacks in NetEmu are a **training model**. But the frames (ARP, DHCP, BPDU) are real, so VLANs, port security, DHCP snooping, Dynamic ARP Inspection and BPDU Guard act on them.

## Why layer 2 is vulnerable

By default a switch:
- **learns MAC addresses** from any incoming frame and trusts them;
- **floods** a frame out of all ports when it does not know where the destination is (broadcast and unknown unicast);
- does not check who sends ARP, DHCP and BPDU.

So anyone with access to a port (a socket in a meeting room, Wi-Fi, a compromised computer) can deceive others in the same segment. L2 attacks are dangerous because they bypass the router and the firewall: they happen **before** them, inside the broadcast domain.

## Attacks and defences

### 1. ARP spoofing (man-in-the-middle)

**Attack.** ARP has no authentication: a host trusts any ARP reply. The attacker sends forged replies: it tells the victims it is the gateway, and tells the gateway it is each of the victims. Now all traffic between the victims and the gateway flows through it. It can read, alter and capture passwords (a man-in-the-middle attack), or cause a denial of service. A variant is gratuitous ARP.

**Defence: Dynamic ARP Inspection (DAI).** The switch checks every ARP on an untrusted port: does the IP+MAC pair match what is known? The source of truth is the **DHCP snooping** table (who leased which address) or **static bindings** `ip source binding` for static addresses. Non-matching ARP is dropped. Ports to other switches and routers are made trusted.

```text
ip dhcp snooping
ip dhcp snooping vlan 1
no ip dhcp snooping information option
interface GigabitEthernet0/1
 ip dhcp snooping trust
 ip arp inspection trust
exit
ip arp inspection vlan 1
```

For static addresses the table is filled by hand:

```text
ip source binding 0001.1111.1111 vlan 1 192.168.1.11 interface Fa0/2
ip arp inspection vlan 1
```

DAI works **on the switch**: an end host cannot protect itself, because it trusts ARP by design.

### 2. MAC flooding (CAM overflow)

**Attack.** A switch has a finite MAC address table (CAM). The attacker floods the switch with frames from thousands of random MAC addresses, the table overflows and the switch fails open, flooding **every** frame out of all ports like a hub. The attacker sees traffic meant for others (the `macof` tool).

**Defence: port security.** On an access port, limit the number of allowed MAC addresses and set a violation action: `protect` (drop silently), `restrict` (drop and count), `shutdown` (disable the port, err-disable). The flood of new addresses disables the offender's port and the table does not overflow.

```text
interface FastEthernet0/10
 switchport mode access
 switchport port-security
 switchport port-security maximum 3
 switchport port-security violation shutdown
 switchport port-security mac-address sticky
```

`sticky` stores learned addresses in the configuration. Port security goes on **user ports**, not on the trunk ports between switches, where there are many changing addresses.

### 3. DHCP attacks

**Rogue DHCP server.** The attacker answers DHCP requests before the real server and hands clients itself as the gateway and DNS: again a man-in-the-middle.

**DHCP starvation.** The attacker requests addresses with thousands of spoofed MACs, the real server's pool runs out and new clients get no address (the `yersinia` tool). Often paired with a rogue server.

**Defence: DHCP snooping.** The switch treats ports as untrusted and **lets DHCP replies (OFFER/ACK) through only from trusted ports** — where the real server or its uplink is. A rogue server on a user port is cut off. Against starvation, port security (a MAC limit) and DHCP rate limiting (`ip dhcp snooping limit rate`) help. As a bonus, snooping builds the binding table for DAI.

```text
ip dhcp snooping
ip dhcp snooping vlan 1
interface GigabitEthernet0/1
 ip dhcp snooping trust
```

### 4. STP root takeover

**Attack.** The Spanning Tree Protocol (STP) also trusts any BPDU. The attacker sends "superior" BPDUs (priority 0) and becomes the root of the tree. The switches rebuild the topology so traffic flows through the attacker: another way to become a man-in-the-middle or to destabilise the network.

**Defence.**
- **BPDU Guard**: a port to an end device must never see a BPDU. If one arrives, the port is disabled at once (err-disable). Enable it on all user ports: `spanning-tree bpduguard enable`, or globally `spanning-tree portfast bpduguard default`.
- **Root Guard**: a port may advertise itself but may not become the **path to the root**. If a superior BPDU arrives, the port goes root-inconsistent (blocked) until the BPDUs stop. Put it on ports to switches that must not be the root: `spanning-tree guard root`.

```text
interface FastEthernet0/10
 spanning-tree portfast
 spanning-tree bpduguard enable
```

BPDU Guard is for ports to hosts (where a BPDU cannot legitimately appear). Root Guard is for ports to other switches that must not be trusted with the root role.

### 5. VLAN hopping

**Double tagging.** An attacker in the native VLAN sends a frame with two 802.1Q tags. The first switch strips the outer tag (it matches the trunk's native VLAN and is not tagged) and forwards the frame over the trunk with the second tag, into another VLAN. The traffic is one-way.

**Switch spoofing.** The attacker pretends to be a switch and negotiates a trunk with DTP, gaining access to all VLANs.

**Defence.**
- turn off trunk auto-negotiation: `switchport nonegotiate`, explicit `switchport mode access` / `trunk`;
- put unused ports into a disabled "quarantine" VLAN and `shutdown`;
- **change the trunk's native VLAN** to a separate, unused one and tag it (`vlan dot1q tag native`), so stripping the outer tag grants no access;
- do not use VLAN 1.

### Others

- **CDP/LLDP**: reveal the model, version and addresses. Disable them on user ports (`no cdp enable`).
- **Broadcast storms**: limit with storm-control.
- **Network access control (802.1X)**: the port passes no traffic until the device authenticates against RADIUS, so a foreign computer never gets onto the network. See the vendor pages.

## A switch hardening baseline

1. Disable unused ports and assign them an unused VLAN.
2. On every user port: `port security`, `BPDU Guard`, `portfast`.
3. Enable `DHCP snooping` and `Dynamic ARP Inspection` in the user VLANs; trust only the uplinks.
4. Explicit port modes, `switchport nonegotiate`, a separate native VLAN, do not use VLAN 1.
5. 802.1X for access control where possible.
6. Disable CDP/LLDP and unused services on external ports.

## How NetEmu models it

### The "LAN attacker" device

Palette → Attacks → "LAN attacker". It is an ordinary host (IP, MAC, DHCP or a static address) connected to a switch, with a list of attacks (the "L2 attacks" tab):

| Attack | What it does | What stops it |
|---|---|---|
| ARP spoofing (MITM) | impersonates the gateway, intercepts the victims' traffic | Dynamic ARP Inspection |
| MAC table flooding | fills the CAM, the switch floods everything out of all ports | port security |
| STP root takeover | becomes the tree root with superior BPDUs | BPDU Guard / Root Guard |

The attacks use real frames and go through normal switching, so VLANs, port security, DHCP snooping, DAI and BPDU Guard act on them. Tools → LAN attacks (`Ctrl+Shift+L`) shows who is attacking, how many frames are intercepted and which defences fired. The attacker forwards intercepted traffic on to the real destination, so the victims notice nothing (a stealthy MITM).

### Defence commands (Cisco IOS)

- Port security: `switchport port-security …` (also on the Cisco page).
- DHCP snooping: `ip dhcp snooping`, `ip dhcp snooping trust`.
- Dynamic ARP Inspection: `ip arp inspection vlan …`, `ip arp inspection trust`, `ip source binding …`, `show ip arp inspection`.
- BPDU Guard / Root Guard: `spanning-tree bpduguard enable`, `spanning-tree guard root`, `spanning-tree portfast bpduguard default`.

## Your own labs

A check for the lab editor:
- `mitm <attacker> [max]`: the attacker intercepts at most the given number of frames (default 0); the check passes when the defence works.

To control an attack in a solution script there is the `@l2 start|stop` directive on the attacker device. STP root takeover is checked by the existing `stproot <switch>` check (the switch is the root again).

## Limits of the model

- The attacks are a training model of three kinds; the defences are implemented for Cisco IOS.
- Rogue DHCP and VLAN hopping are covered in theory; their basis in NetEmu (DHCP snooping, trunk modes and the native VLAN) is configurable, but there is no separate "rogue server" device.
- Interception is counted by the frames delivered to the attacker through ARP spoofing or CAM overflow; the number is a rough measure, not an exact packet count.
