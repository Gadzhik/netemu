# Атаки на втором уровне (LAN) и защита коммутаторов

Этот раздел о том, как атакуют внутри локальной сети — на канальном уровне (L2), где работают коммутаторы, — и как коммутаторы от этого защищают. Злоумышленнику здесь не нужны уязвимости в программах: он пользуется самим устройством протоколов ARP, DHCP и STP, которые по умолчанию доверяют любому в сети. В NetEmu это можно показать: устройство «Атакующий (LAN)» проводит атаки настоящими кадрами, а защита настраивается на коммутаторе так же, как на реальном оборудовании Cisco.

> Атаки в NetEmu — **учебная модель**. Но кадры (ARP, DHCP, BPDU) настоящие, поэтому на них действуют VLAN, port security, DHCP snooping, Dynamic ARP Inspection и BPDU Guard.

## Почему второй уровень уязвим

Коммутатор по умолчанию:
- **учит MAC-адреса** из любого пришедшего кадра и верит им;
- **рассылает** кадр во все порты, если не знает, где получатель (broadcast и unknown unicast);
- не проверяет, кто отправляет ARP, DHCP и BPDU.

Поэтому любой, кто получил доступ к порту (розетка в переговорной, Wi-Fi, взломанный компьютер), может обманывать других в том же сегменте. Атаки L2 опасны тем, что обходят маршрутизатор и межсетевой экран: они происходят **до** них, внутри широковещательного домена.

## Виды атак и защита

### 1. Подмена ARP (ARP spoofing, man-in-the-middle)

**Атака.** ARP не имеет аутентификации: хост верит любому ARP-ответу. Атакующий рассылает поддельные ответы: жертвам говорит, что он — шлюз, а шлюзу — что он каждая из жертв. Теперь весь трафик между жертвами и шлюзом идёт через него. Он может его читать, изменять, перехватывать пароли (атака «человек посередине»), а также устроить отказ в обслуживании. Разновидность — gratuitous ARP (самопроизвольный ARP).

**Защита — Dynamic ARP Inspection (DAI).** Коммутатор проверяет каждый ARP на недоверенном порту: соответствует ли пара «IP + MAC» тому, что известно. Источник истины — таблица **DHCP snooping** (кто какой адрес получил по DHCP) или **статические привязки** `ip source binding` для статических адресов. Несоответствующие ARP отбрасываются. Порты к другим коммутаторам и маршрутизаторам делают доверенными.

```text
ip dhcp snooping
ip dhcp snooping vlan 1
no ip dhcp snooping information option
interface GigabitEthernet0/1
 ip dhcp snooping trust
 ip arp inspection trust
exit
ip arp inspection vlan 1
```

Для статических адресов таблицу заполняют вручную:

```text
ip source binding 0001.1111.1111 vlan 1 192.168.1.11 interface Fa0/2
ip arp inspection vlan 1
```

DAI работает **на коммутаторе**: конечный узел не может защититься сам, потому что доверяет ARP по устройству протокола.

### 2. Переполнение MAC-таблицы (MAC flooding, CAM overflow)

**Атака.** У коммутатора конечная таблица MAC-адресов (CAM). Атакующий заваливает коммутатор кадрами с тысячами случайных MAC-адресов, таблица переполняется, и коммутатор переходит в режим «отказа» — рассылает **все** кадры во все порты, как концентратор. Атакующий видит трафик, предназначенный другим (инструмент — `macof`).

**Защита — port security.** На порту доступа ограничивают число разрешённых MAC-адресов и задают действие при нарушении: `protect` (молча отбрасывать), `restrict` (отбрасывать и считать), `shutdown` (отключить порт, err-disable). Лавина новых адресов отключит порт нарушителя, таблица не переполнится.

```text
interface FastEthernet0/10
 switchport mode access
 switchport port-security
 switchport port-security maximum 3
 switchport port-security violation shutdown
 switchport port-security mac-address sticky
```

`sticky` запоминает выученные адреса в конфигурации. Port security ставят на **порты к пользователям**, а не на магистральные порты между коммутаторами, где адресов много и они меняются.

### 3. Атаки на DHCP

**Поддельный DHCP-сервер (rogue DHCP).** Атакующий отвечает на запросы DHCP раньше настоящего сервера и выдаёт клиентам себя в качестве шлюза и DNS — снова «человек посередине».

**Истощение пула (DHCP starvation).** Атакующий запрашивает адреса с тысячами поддельных MAC, пул настоящего сервера заканчивается, новые клиенты не получают адрес (инструмент — `yersinia`). Часто сочетается с поддельным сервером.

**Защита — DHCP snooping.** Коммутатор считает порты недоверенными и **пропускает ответы DHCP (OFFER/ACK) только с доверенных портов** — там, где стоит настоящий сервер или аплинк к нему. Поддельный сервер на порту пользователя отсекается. Против истощения помогает port security (лимит MAC) и ограничение частоты DHCP (`ip dhcp snooping limit rate`). Побочно snooping строит таблицу привязок для DAI.

```text
ip dhcp snooping
ip dhcp snooping vlan 1
interface GigabitEthernet0/1
 ip dhcp snooping trust
```

### 4. Захват корня STP (STP root takeover)

**Атака.** Протокол связующего дерева (STP) тоже доверяет любому BPDU. Атакующий отправляет «лучшие» BPDU (с приоритетом 0) и становится корнем дерева. Коммутаторы перестраивают топологию так, что трафик идёт через атакующего, — ещё один способ встать «человеком посередине» или вызвать нестабильность сети.

**Защита.**
- **BPDU Guard**: на порту к конечному устройству BPDU быть не должно. Если BPDU пришёл, порт сразу отключается (err-disable). Включают на всех пользовательских портах: `spanning-tree bpduguard enable` или глобально `spanning-tree portfast bpduguard default`.
- **Root Guard**: на порту разрешено объявлять себя, но запрещено становиться **путём к корню**. Если приходит лучший BPDU, порт переводится в состояние root-inconsistent (блокируется), пока BPDU не прекратятся. Ставят на порты к коммутаторам, которые не должны быть корнем: `spanning-tree guard root`.

```text
interface FastEthernet0/10
 spanning-tree portfast
 spanning-tree bpduguard enable
```

BPDU Guard — для портов к хостам (там BPDU быть не может вовсе). Root Guard — для портов к другим коммутаторам, которым нельзя доверить роль корня.

### 5. Перескок между VLAN (VLAN hopping)

**Двойное тегирование (double tagging).** Атакующий в «родном» (native) VLAN отправляет кадр с двумя метками 802.1Q. Первый коммутатор снимает внешнюю метку (она совпадает с native VLAN магистрали и не тегируется) и пересылает кадр по магистрали со второй меткой — в чужой VLAN. Трафик уходит в один конец.

**Switch spoofing.** Атакующий притворяется коммутатором и по протоколу DTP договаривается о транке, получая доступ ко всем VLAN.

**Защита.**
- отключить автосогласование транков: `switchport nonegotiate`, явные режимы `switchport mode access` / `trunk`;
- неиспользуемые порты — в выключенный «карантинный» VLAN и `shutdown`;
- **сменить native VLAN магистрали** на отдельный, никем не используемый, и тегировать его (`vlan dot1q tag native`), чтобы снятие внешней метки не давало доступа;
- не использовать VLAN 1.

### Прочее

- **CDP/LLDP**: раскрывают модель, версию, адреса. Отключают на портах к пользователям (`no cdp enable`).
- **Штормы широковещания**: ограничивают storm-control.
- **Контроль доступа к сети (802.1X)**: порт не пропускает трафик, пока устройство не пройдёт аутентификацию по RADIUS, — чужой компьютер вообще не попадает в сеть. См. разделы вендоров.

## Общий принцип защиты коммутатора (baseline)

1. Отключить неиспользуемые порты, назначить им неиспользуемый VLAN.
2. На всех портах к пользователям: `port security`, `BPDU Guard`, `portfast`.
3. Включить `DHCP snooping` и `Dynamic ARP Inspection` в пользовательских VLAN, доверенными сделать только аплинки.
4. Явные режимы портов, `switchport nonegotiate`, отдельный native VLAN, не использовать VLAN 1.
5. 802.1X для контроля доступа, где возможно.
6. Отключить CDP/LLDP и неиспользуемые службы на внешних портах.

## Как это устроено в NetEmu

### Устройство «Атакующий (LAN)»

Палитра → «Атаки» → «LAN attacker». Это обычный хост (IP, MAC, DHCP или статический адрес), подключённый к коммутатору, со списком атак (вкладка «Атаки L2»):

| Атака | Что делает | Чем остановить |
|---|---|---|
| Подмена ARP (MITM) | выдаёт себя за шлюз, перехватывает трафик жертв | Dynamic ARP Inspection |
| Переполнение MAC-таблицы | заполняет CAM, коммутатор рассылает всё во все порты | port security |
| Захват корня STP | лучшими BPDU становится корнем дерева | BPDU Guard / Root Guard |

Атаки идут настоящими кадрами и проходят обычную коммутацию, поэтому на них действуют VLAN, port security, DHCP snooping, DAI и BPDU Guard. «Инструменты → Атаки в сети (L2)» (`Ctrl+Shift+L`) показывает, кто атакует, сколько кадров перехвачено и какие защиты сработали. Перехваченный трафик атакующий пересылает дальше настоящему получателю, поэтому жертвы ничего не замечают (скрытый MITM).

### Команды защиты (Cisco IOS)

- Port security — `switchport port-security …` (есть и в разделе Cisco).
- DHCP snooping — `ip dhcp snooping`, `ip dhcp snooping trust`.
- Dynamic ARP Inspection — `ip arp inspection vlan …`, `ip arp inspection trust`, `ip source binding …`, `show ip arp inspection`.
- BPDU Guard / Root Guard — `spanning-tree bpduguard enable`, `spanning-tree guard root`, `spanning-tree portfast bpduguard default`.

## Готовые лабораторные

| Работа | Что изучается | Решение |
|---|---|---|
| 31. Подмена ARP и DAI | перехват трафика через ARP, man-in-the-middle | Dynamic ARP Inspection со статическими привязками |
| 32. Переполнение MAC-таблицы и port security | CAM overflow, прослушивание чужого трафика | port security на порту пользователя |
| 33. Захват корня STP и BPDU Guard | подмена корня дерева | BPDU Guard на порту к устройству |

## Свои задания

Проверка для редактора задания:
- `mitm <атакующий> [макс]` — атакующий перехватывает не больше указанного числа кадров (по умолчанию 0): проверка проходит, когда защита работает.

Для управления атакой в сценарии решения служит директива `@l2 start|stop` на устройстве-атакующем. Захват корня STP проверяется существующей проверкой `stproot <коммутатор>` (коммутатор снова корень).

## Ограничения модели

- Атаки — учебная модель трёх типов; защиты реализованы для Cisco IOS.
- Подделка DHCP и перескок между VLAN описаны в теории; в NetEmu их основа (DHCP snooping, режимы транка и native VLAN) настраивается, но отдельного устройства-«поддельного сервера» нет.
- Перехват считается по кадрам, доставленным атакующему подменой ARP или переполнением CAM; число — условная мера, а не точный счётчик пакетов.
